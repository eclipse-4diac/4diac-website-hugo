## Enhancements and Fixes in 4diac IDE

- **EtherCAT & I/O Support**
  - Improved EtherCAT controller configuration
    - Renamed `ECController` input `ControllerIndex` to `ControllerId` to match 4diac FORTE and ensure correct parameter deployment
    - Changed the default `UpdateInterval` to 1 ms to match the runtime
  - Changed the `GPIOChip`'s `VALUE` input from `WSTRING` to `STRING`, matching the updated 4diac FORTE implementation
  - Corrected the generic class name of `PROVIDE_ARR` function blocks to ensure proper runtime compatibility

- **AsciiDoc Documentation Editor**
  - Added drag-and-drop support for images from the file explorer
    - Images are automatically copied into the `.assets` folder, as with the existing image insertion dialog

- **Structured Text & Refactoring**
  - Fixed case-sensitive package name validation for declarations and wildcard imports
  - Improved FB pin lookup in the ST Editor
  - Improved rename refactoring by providing the URI of renamed elements to rename participants

- **Library Management & Validation**
  - Added validation to ensure unique symbolic names for library dependencies

- **Code Quality & Maintenance**
  - Finished migrating 4diac IDE components to Eclipse Platform's `ILog`
  - Deprecated `FordiacLogHelper` for removal to discourage further use

## Enhancements and Fixes in 4diac FORTE

- **EtherCAT & I/O Support**
  - Improved EtherCAT master initialization
    - Ensured all devices are configured before activating the master, fixing problems with multi-device configurations and devices without PDOs
    - Corrected the default `ECController` update interval to 1 ms, preventing unintended continuous execution after deployment
  - Fixed `GPIOChip` connection handling
    - Changed the `VALUE` input to `STRING`
    - Fixed a dangling reference that could prevent connections when using longer handle identifiers
  - Removed the legacy I/O interface

- **Network Communication**
  - Improved communication channel management
    - Reused existing communication channels on repeated open operations instead of recreating them
    - Added more detailed result codes for network errors to improve diagnostics
    - Introduced a common socket wrapper for communication channel implementations
  - Added comprehensive communication channel and network tests

## Enhancements and Fixes in 4diac Documentation

- **I/O Configuration**
  - Updated the I/O documentation to reflect the removal of legacy I/O support

Many thanks to all contributors for their work and their feedback!
